# Результаты упрощения AI Buddy

Проверено 14 ноября 2026 года. Базовая ревизия до рефакторинга: `55346b7`.

Все пути ниже указаны относительно `backend/`. Один модуль `ai-buddy`, серверные команды `cmd/tracker` и `cmd/ticket`, общая инфраструктура
`internal/platform`, общие административные команды `cmd/migrate` и `cmd/seed`.
Удалены шаблон и промежуточный адаптер прогресса. Предметные модели, HTTP-контракты,
раздельные БД и HTTP-взаимодействие Ticket → Tracker сохранены. Все четыре исходных SQL-файла
совпадают с исходной ревизией побайтно. Имена Compose-проектов и томов сохранены явно.

## Проверки

`./scripts/check.sh` проходит форматирование, `go vet ./...`, сборку четырёх команд,
`go test -race` с тремя независимыми профилями и Compose config обоих сервисов.

| Группа runtime-кода | Покрыто / всего операторов | Покрытие |
| --- | ---: | ---: |
| Tracker: `cmd/tracker`, `internal/tracker` | 371 / 387 | 95,87% |
| Ticket: `cmd/ticket`, `internal/ticket` | 217 / 228 | 95,18% |
| Platform: `internal/platform`, `cmd/migrate`, `cmd/seed` | 310 / 322 | 96,27% |

Каждый профиль инструментирует только свою группу. Общий код не увеличивает покрытие сервисов,
тестовые помощники исключены. Блоки одной позиции, повторённые разными тестовыми бинарниками,
объединяются; порог строго выше 80% проверяется по операторам, без округления.
Профили и подробные журналы: `/tmp/ai-buddy-check` (настраивается `CHECK_OUTPUT_DIR`).

Сохранены проверки нормализации задач, идемпотентности и конфликтов, завершения своей задачи
с сохранением первой даты, календарной просрочки, прогресса и следующей задачи, закрепления
стажёров за наставником. Для Ticket сохранены выбор и фиксация получателя, отсутствие наставника,
ошибки Tracker, повтор без HTTP-запроса, конфликт содержимого и фильтрация списков.
Авторизация подробно проверяется один раз; подключение ролей и Bearer-ключей проверяется на
маршрутах обоих сервисов. Полные JSON-контракты проверяются рядом с HTTP DTO.

Сохранены PostgreSQL-тесты миграций (включая down/up обоих сервисов), ограничений, сессий,
конкурентной идемпотентности, повторного seed и отката транзакций. Настройка временных схем
и общие HTTP/JSON-помощники вынесены в `internal/testutil`.

**Ограничения проверки среды:** `TEST_DATABASE_URL` не задан, PostgreSQL-интеграции явно
пропущены. Docker CLI доступен, но Docker daemon отсутствует (проверка `docker info` не может
подключиться к сокету). Поэтому сборки обоих образов и запуск двух отдельных БД с реальным
вызовом Ticket → Tracker не проверены. Compose config проверен без daemon; локальная сборка
всех Go-команд и HTTP-тесты с локальными серверами выполнены.

## Объём кода

Метод совпадает с исходным измерением: Go-файлы, без пустых строк и строк комментариев;
`*_test.go` и файлы тестовых помощников `testdb`/`testutil` относятся к тестам.
Обычное форматирование `gofmt` сохранено. Скрипт воспроизводит исходные значения плана:

```sh
./scripts/count-go-lines.py --git-ref 55346b7
./scripts/count-go-lines.py --git-ref 55346b7 --services-only
./scripts/count-go-lines.py
```

| Область | До: приложение | После | Изменение | До: тесты | После | Изменение |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Весь репозиторий, включая прежний шаблон | 3 472 | 2 527 | −945 (−27,22%) | 5 088 | 3 390 | −1 698 (−33,37%) |
| Tracker + Ticket + общая инфраструктура, без шаблона | 2 991 | 2 527 | −464 (−15,51%) | 4 130 | 3 390 | −740 (−17,92%) |

Сокращение без учёта шаблона получено объединением auth, конфигурации, HTTP-обвязки,
исполнителя миграций и загрузчика пользователей; удалением адаптера прогресса и повторных
тестовых настроек/проверок. Добавлены проверки CLI и полного JSON-контракта Ticket.

Код, Go-модуль, Dockerfile, скрипты и развёртывание перенесены в `backend/`.
Команды проверки и подсчёта строк выполняются из `backend/`; HTTP-контракты и имена
Compose-проектов, сетей и томов сохранены.
