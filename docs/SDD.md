# SDD AI Buddy

AI Buddy помогает стажёрам находить внутренние документы, следить за задачами и обращаться к наставнику.

## Архитектура

Один Go-процесс, один HTTP API, одна PostgreSQL с pgvector и один пул соединений.
Buddy, Tracker, Ticket и Wiki — внутренние пакеты с бизнес-логикой. Один бинарник
`cmd/server`: `serve` (по умолчанию), `migrate up|down|status`, `seed`, `index [--full]`.
Запуск: подключение к БД → общие миграции → локальный транзакционный seed →
восстановление Buddy → HTTP. Seed не перезаписывает существующие данные.

Профили и связи принадлежат общей БД. Внешние ключи защищают владельцев,
отправителей и получателей; назначения ограничены ролями и общей командой.
Старая схема и миграционная совместимость не сохраняются. Серверных сессий,
OIDC, сервисных ключей и внутренних HTTP-запросов нет.

Ollama выполняет `embeddinggemma:300m` для Wiki и `qwen3.5:4b` для Buddy.
Контекст Buddy — 4096 токенов, `think:false`. Модели загружаются отдельной командой
профиля Compose `tools`; индексация Wiki запускается явно. API стартует без
моделей и индекса. Readiness проверяет только БД.

Compose содержит приложение, PostgreSQL и Ollama, без внешней shared-сети.
Публичный порт приложения — 8080, база знаний монтируется read-only.
Кэш моделей можно переиспользовать через `OLLAMA_VOLUME_NAME`.
Frontend не входит в эту работу. Будущий UI и API работают на одном origin,
публичный доступ — через единый HTTPS-host.

## Выбор пользователя и доступ

`GET /api/users` публично возвращает шесть профилей двух команд с сортировкой по ID.
Стабильный ID совпадает с username, например `intern.backend.1`.
`intern.platform.2` не имеет наставника. Общий профиль: `id`, `name`, `username`,
`email`, `role`, `team`, `start_date`, `goals`, `expectations`.

Frontend устанавливает `demo_user=<id>; Path=/; SameSite=Lax`. Cookie автоматически
отправляется fetch и EventSource. Backend загружает профиль из БД; роль и команда
не принимаются от браузера или модели. Это демо-переключатель без проверки подлинности.
`GET /api/me` возвращает выбранный профиль. Отсутствующая, пустая или неизвестная
cookie даёт JSON 400; ошибка БД — JSON 503, без пользователя по умолчанию.

Выбранный профиль закрепляется за запуском Buddy. Переключение cookie не меняет
начавшуюся генерацию. UI закрывает прежний EventSource и загружает данные нового профиля.
Стажёр видит собственные диалоги, задачи и отправленные тикеты; Buddy доступен стажёрам.
Наставник видит только закреплённых стажёров и адресованные ему тикеты.
Wiki использует команду профиля: документы `common` доступны всем выбранным профилям,
остальные — своей команде. Ссылки относительные: `/api/documents/{id}`.

## Buddy: чат и действия

Стажёр создаёт диалоги и возвращается к своей истории. Через чат он ищет документы,
смотрит прогресс, создаёт задачи, завершает их и отправляет вопросы наставнику.
Быстрые действия запускают те же сценарии, что текстовый запрос.

Buddy хранит диалоги, сообщения, запуски, SSE-события и подтверждения в PostgreSQL.
Buddy работает в одной реплике. После рестарта незавершённые операции должны
помечаться ошибкой без автоматического повтора.
На чат допускается один активный запуск, отправка сообщения требует Idempotency-Key.
На один запуск допускается не более шести вызовов инструментов.
Финальный ответ должен передаваться потоково.
Подтверждение фиксирует поля действия; ручной повтор сохраняет ключ идемпотентности.
MCP-инструменты напрямую вызывают Go-сервисы Wiki, Tracker и Ticket;
бэкенд закрепляет выбранный профиль за запуском. Ответ передаётся через SSE:
этап работы, текст и карточки источников или результатов операций.
После обрыва соединения ответ продолжает формироваться; переподключение восстанавливает его без дублей.
При остановке Buddy должен дожидаться сохранения генерации и начатых подтверждений
до закрытия соединения с БД.

Создание задачи или тикета требует подтверждения черновика. Явная просьба завершить
однозначно указанную задачу выполняется сразу; при неоднозначности Buddy просит уточнение.
Ошибки сервисов видны пользователю и допускают ручной повтор.
Повтор создания с тем же ключом идемпотентности и содержимым возвращает прежнюю запись;
изменение содержимого при том же ключе вызывает конфликт.

## Tracker: задачи и прогресс

У стажёра один назначенный наставник либо назначения нет. У наставника может быть несколько стажёров.
Стажёр создаёт и завершает свои задачи через Tracker или Buddy. Редактирование задач в текущую версию не входит.
Название и дедлайн обязательны, описание опционально. Дедлайн — календарная дата;
задача становится просроченной со следующего дня по часовому поясу приложения.
Повтор завершения сохраняет прежнее состояние.

Прогресс включает список задач со статусами и сроками, счётчик выполненных, сведения о стажёре
и наставнике. Следующий шаг — первая просроченная незавершённая задача, иначе ближайшая по сроку;
при равенстве используется порядок списка. Когда всё выполнено, показывается соответствующее сообщение.

Наставник открывает дашборд закреплённых стажёров и просматривает их прогресс без редактирования.
Ticket получает назначенного наставника из общего repository назначений.

## Ticket: вопросы наставнику

Тикет содержит отправителя, получателя, вопрос и описание. Оба текстовых поля обязательны.
Получателя определяет Ticket из назначений в общей БД. Без назначения тикет не создаётся.
Получатель фиксируется при создании: смена наставника не изменяет старые тикеты
и не мешает повторному чтению по тому же ключу идемпотентности.

Если Wiki не находит ответ, Buddy предлагает обратиться к наставнику. Пользователь проверяет
и редактирует черновик перед отправкой. Стажёр видит свои отправленные тикеты,
наставник — свои входящие.

## Wiki: документы и RAG

Markdown-файлы в `knowledge-base/` — источник истины, PostgreSQL — обновляемый поисковый индекс.
Первая папка определяет доступ: `common` или название команды. Вложенные папки наследуют доступ.

Индексатор разбивает документы на фрагменты и получает эмбеддинги через Ollama.
Он переиспользует неизменённые данные и атомарно публикует обновления; ошибка сохраняет прежний индекс.
Смена модели требует полного пересчёта. Индексация запускается явно, отдельно от сервера.

Гибридный поиск объединяет полнотекстовый и векторный поиск, проверяет доступ до отбора
и возвращает до трёх фрагментов с документом, разделом и ссылкой. При отсутствии совпадений
возвращается пустой список. Buddy формирует ответ на основе найденных фрагментов и показывает источники.
Если Ollama недоступна или модель не соответствует индексу, поиск возвращает ошибку,
но чтение документов продолжает работать.

Wiki предоставляет JSON API поиска, списка документов и получения исходного Markdown.
Веб-интерфейс должен отображать Markdown-документы.

## Критерии приёмки

- Пользователи видят только доступные им документы, диалоги, задачи и тикеты.
- Поиск находит документы по словам и смыслу, учитывает права доступа и возвращает источники.
- Обновление индекса отражает изменения документов; ошибка индексации сохраняет прежний индекс.
- Tracker корректно показывает сроки, просроченные задачи и прогресс закреплённых стажёров.
- Создание задач и тикетов через Buddy требует подтверждения; повтор запроса не создаёт дубликаты.
- Переподключение к SSE восстанавливает события без дублей.
- Ошибки зависимостей видны пользователю; недоступность сервиса не расширяет права доступа.

## API и документация

Единый [OpenAPI 3.1.1](../backend/api/openapi.yaml): 24 операции, группы Users,
Buddy, Tracker, Ticket и Wiki. Один список серверов: публичный HTTPS-host и
`http://localhost:8080`. Старые маршруты входа и внутреннего транспорта удалены.
Тела бизнес-запросов, envelopes, идемпотентность и формат SSE сохраняются.

Конфигурация и команды запуска и проверок: [README бэкенда](../backend/README.md).
