# SDD AI Buddy

AI Buddy помогает стажёрам находить внутренние документы, следить за задачами и обращаться к наставнику.
Реализованы Buddy, Tracker, Ticket и Wiki, вход через Authentik и интеграция с локальными моделями Ollama.
React-интерфейсы запланированы.

## Архитектура

Система состоит из четырёх отдельных Go-сервисов:

- **Buddy** — чат, история диалогов и вызовы инструментов агента.
- **Tracker** — задачи, прогресс и назначения наставников.
- **Ticket** — вопросы стажёров наставникам.
- **Wiki** — документы и поиск по базе знаний.

У каждого сервиса собственная PostgreSQL, сессии и Compose-конфигурация.
Сервисы обращаются к данным друг друга через API. Общая инфраструктура бэкенда отвечает за
авторизацию, конфигурацию, подключение к БД и запуск HTTP-сервера.

Authentik хранит пользователей, роли и команды. Ollama выполняет модели локально на CPU:
`embeddinggemma:300m` для поиска Wiki и `qwen3.5:4b` для ответов Buddy и вызова инструментов.
Для Buddy приняты контекст 4096 токенов и `think: false`.

Приложения работают на домашнем сервере. Публичный HTTPS-трафик проходит через Caddy на VPS
и туннель Rathole. Каждый сервис имеет свой поддомен; будущий React-интерфейс использует API
на том же домене. Frontend — один проект с общими компонентами и отдельными сборками сервисов.

## Вход и доступ

Каждый сервис использует собственный OIDC-клиент Authentik и серверную сессию.
Сессия хранит ID пользователя, роль и команду до следующего входа. Cookies защищены HTTPS.

- Стажёр видит свои диалоги, задачи и отправленные тикеты. Чат Buddy доступен только стажёрам.
- Наставник видит прогресс закреплённых стажёров и адресованные ему тикеты.
- Документы `common` доступны всем авторизованным; остальные — только своей команде.
- Межсервисные запросы защищены API-ключами. ID пользователя берётся из доверенного контекста;
  модель и браузер не определяют права доступа.
- Для поиска от Buddy Wiki получает актуальную команду из Authentik отдельным токеном чтения
  пользователей. При сбое Authentik такой поиск недоступен. Браузерные запросы используют сессию Wiki.

## Buddy: чат и действия

Стажёр создаёт диалоги и возвращается к своей истории. Через чат он ищет документы,
смотрит прогресс, создаёт задачи, завершает их и отправляет вопросы наставнику.
Быстрые действия запускают те же сценарии, что текстовый запрос.

Buddy хранит диалоги, сообщения, запуски, SSE-события и подтверждения в PostgreSQL.
Одна реплика; после рестарта незавершённые операции помечаются ошибкой без автоповтора.
На чат допускается один активный запуск, отправка сообщения требует Idempotency-Key.
Официальный MCP Go SDK соединяет клиента и сервер в памяти на каждый запуск;
схемы инструментов для нативного Ollama API получаются через tools/list.
Выбор инструментов — без streaming, максимум шесть вызовов, финальный ответ — streaming без инструментов.
Подтверждение фиксирует поля и использует постоянный ключ из ID действия при ручных повторах.
MCP-инструменты вызывают API Wiki, Tracker и Ticket;
бэкенд подставляет пользователя и сервисные ключи. Ответ передаётся через SSE:
этап работы, текст и карточки источников или результатов операций.
После обрыва соединения ответ продолжает формироваться; переподключение восстанавливает его без дублей.

Создание задачи или тикета требует подтверждения черновика. Явная просьба завершить
однозначно указанную задачу выполняется сразу; при неоднозначности Buddy просит уточнение.
Ошибки сервисов видны пользователю и допускают ручной повтор.
Повтор создания с тем же ключом идемпотентности и содержимым возвращает прежнюю запись;
изменение содержимого при том же ключе вызывает конфликт.

## Tracker: задачи и прогресс

У стажёра один назначенный наставник либо назначения нет. У наставника может быть несколько стажёров.
Стажёр создаёт и завершает свои задачи через Tracker или Buddy. Редактирование задач в текущую версию не входит.
Название и дедлайн обязательны, описание опционально. Дедлайн — календарная дата;
задача становится просроченной со следующего дня по часовому поясу приложения.
Повтор завершения сохраняет прежнее состояние.

Прогресс включает список задач со статусами и сроками, счётчик выполненных, сведения о стажёре
и наставнике. Следующий шаг — первая просроченная незавершённая задача, иначе ближайшая по сроку;
при равенстве используется порядок списка. Когда всё выполнено, показывается соответствующее сообщение.

Наставник открывает дашборд закреплённых стажёров и просматривает их прогресс без редактирования.
Ticket получает назначенного наставника через отдельный внутренний API Tracker.

## Ticket: вопросы наставнику

Тикет содержит отправителя, получателя, вопрос и описание. Оба текстовых поля обязательны.
Получателя определяет Ticket через Tracker. Без назначения тикет не создаётся;
при сбое Tracker операция возвращает ошибку.

Если Wiki не находит ответ, Buddy предлагает обратиться к наставнику. Пользователь проверяет
и редактирует черновик перед отправкой. Стажёр видит свои отправленные тикеты,
наставник — свои входящие.

## Wiki: документы и RAG

Markdown-файлы в `knowledge-base/` — источник истины, PostgreSQL — обновляемый поисковый индекс.
Первая папка определяет доступ: `common` или название команды. Вложенные папки наследуют доступ.

Индексатор разбивает документы на фрагменты и получает эмбеддинги через Ollama.
Он переиспользует неизменённые данные и атомарно публикует обновления; ошибка сохраняет прежний индекс.
Смена модели требует полного пересчёта. Индексация запускается явно, отдельно от сервера.

Гибридный поиск объединяет полнотекстовый и векторный поиск, проверяет доступ до отбора
и возвращает до трёх фрагментов с документом, разделом и ссылкой. При отсутствии совпадений
возвращается пустой список. Buddy формирует ответ на основе найденных фрагментов и показывает источники.
Если Ollama недоступна или модель не соответствует индексу, поиск возвращает ошибку,
но чтение документов продолжает работать.

Wiki предоставляет JSON API поиска, списка документов и получения исходного Markdown.
Будущий React-интерфейс отображает Markdown готовой библиотекой.

## Приёмка и инструкции

Проверяем доступы, поиск по словам и смыслу, обновление индекса, прогресс, подтверждение действий,
идемпотентность, восстановление SSE и обработку ошибок зависимостей.
Чужие документы, диалоги, задачи и тикеты недоступны.

Общая проверка бэкенда включает форматирование, race-тесты, vet, сборки и Compose validation.
Покрытие каждой группы — Tracker, Ticket, Wiki и общей инфраструктуры — строго выше 80%.

Структура кода, команды и запуск описаны в [README бэкенда](../backend/README.md).
Настройки и эксплуатационные подробности: [Authentik](../backend/deploy/authentik/README.md),
[Ollama](../backend/deploy/ollama/README.md), [Tracker](../backend/deploy/tracker/README.md),
[Ticket](../backend/deploy/ticket/README.md) и [Wiki](../backend/deploy/wiki/README.md).
