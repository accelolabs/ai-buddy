# Go: контексты и тайм-ауты

> Данные в этом документе тестовые и вымышленные. Команда «Маяк», её процессы и примеры придуманы. Все совпадения с реальными лицами, организациями и событиями случайны. Документ не является регламентом Авито.

## Передаём отмену вместе с работой

Мы принимаем `context.Context` первым аргументом функций, которые выполняют ввод-вывод. В HTTP-обработчике начинаем с `r.Context()` и передаём его в сервис, репозиторий и исходящий запрос. Так отмена запроса доходит до зависимостей. Контекст сообщает об отмене; наш код и используемый драйвер должны её обрабатывать. Сам по себе тайм-аут не останавливает произвольную горутину. Это следует из модели [пакета context](https://pkg.go.dev/context).

Мы не заменяем родительский контекст на `context.Background()` внутри репозитория: иначе теряем связь с запросом. Для фоновой обработки создаём отдельную задачу с владельцем, сроком выполнения и понятной политикой повторов.

## Делим бюджет запроса

В учебном сервисе мы выделяем запросу до двух секунд, а чтению из БД — до 400 мс. Это стартовые значения для эксперимента, которые мы пересматриваем по измерениям. Дочерний тайм-аут не продлевает более ранний дедлайн родителя.

```go
func loadTitle(ctx context.Context, db *sql.DB, id int64) (string, error) {
    queryCtx, cancel := context.WithTimeout(ctx, 400*time.Millisecond)
    defer cancel()

    var title string
    err := db.QueryRowContext(queryCtx,
        "SELECT title FROM articles WHERE id = $1", id).Scan(&title)
    return title, err
}
```

Мы вызываем `cancel` даже при успешном завершении, чтобы освобождать связанные ресурсы. Официальный пример [отмены операций БД в Go](https://go.dev/doc/database/cancel-operations) объясняет этот приём. Для исходящего HTTP-вызова создаём запрос через `http.NewRequestWithContext` и закрываем тело ответа.

## Разбираем превышение времени

Когда растёт число `context deadline exceeded`, мы сначала сравниваем длительность запроса, ожидание соединения и время работы зависимости. Увеличиваем лимит только после понимания причины: длинная очередь может означать нехватку соединений или перегрузку. Мы различаем отмену клиентом и истечение собственного бюджета в логах, сохраняя операцию и идентификатор трассировки.

При проверке мы отменяем родительский контекст во время медленного вызова и убеждаемся, что работа завершается. Отдельно проверяем, что повтор запроса укладывается в оставшийся общий бюджет. Правила безопасных повторов описаны в [контрактах HTTP](http-contracts.md).
